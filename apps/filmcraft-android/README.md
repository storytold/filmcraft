# FilmCraft Android

Android mobile runner for FilmCraft using `eframe` and `android-activity`.

## Prerequisites

1. **Android NDK** (version r25 or newer) and Android SDK.
2. Rust target for your test device / emulator architecture:
   ```bash
   rustup target add aarch64-linux-android
   # or x86_64 for emulators:
   rustup target add x86_64-linux-android
   ```
3. `cargo-apk`:
   ```bash
   cargo install cargo-apk
   ```

## Building & Running

Run directly on a connected device or emulator with:

```bash
cargo apk run -p filmcraft-android --target aarch64-linux-android
```

Or with the project task runner (`ANDROID_HOME` and `ANDROID_NDK_ROOT` must be set):

```bash
cargo xtask android --run
```

## Files, settings and storage

- **Settings, shortcuts, presets, auto-save and crash recovery** live in the app's private data
  folder, so they are kept between launches.
- **File dialogs** (Browse files, Open, Save, choose a folder, Locate) open a file browser drawn
  inside the app. Android's own picker is a Java activity that returns `content://` URIs, which the
  engine cannot read, so the app browses the paths it can read directly. The browser starts in
  shared storage (Movies, DCIM, Music, Download) and in the app's own folders.
- **Permission:** to see media in shared storage, allow FilmCraft to read it in Settings > Apps >
  FilmCraft > Permissions (Photos and videos, Music and audio). The app does not ask for it itself
  yet, and the browser says so when a folder cannot be read.
- The launcher icons are copies of the app icon (`assets/app-icon`); `cargo xtask android` generates the
  resources under `target/android-res` before it calls cargo-apk, so use it instead of calling
  `cargo apk` directly.
- The manifest is generated by cargo-apk from `[package.metadata.android]` in `Cargo.toml`
  (permissions included); its version is the workspace version.
