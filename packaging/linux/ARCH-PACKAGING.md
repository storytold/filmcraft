# Arch Linux x86_64 package

`build-deb.sh` remains the entry point. Debian packaging is unchanged when `FILMCRAFT_ARCH_PACKAGE_DIR` is unset. To emit both packages from its existing staged `usr/` tree, set `FILMCRAFT_DEB_ARCHES=x86_64` and `FILMCRAFT_ARCH_PACKAGE_DIR=../dist-test/0.11.0/arch-x86_64`; any other Debian architecture selection is refused. The Arch helper consumes only `$stage/usr`: it does not copy `DEBIAN/control`, Debian postinst, or the Ubuntu libstdc++ `.deb`.

Arch `pkgver` is independent of Debian's `FILMCRAFT_PACKAGE_VERSION`: `FILMCRAFT_ARCH_PACKAGE_VERSION` defaults to `<workspace-version>-1` and accepts an optional numeric epoch, a valid pkgver, and a numeric/dotted pkgrel. For the first release, both formats use `0.11.0-1`; a later Debian test revision can leave Arch on the stable version.

The `.PKGINFO` uses `xdata = pkgtype=pkg`, includes pkgrel in `pkgver`, and sets `arch = x86_64`. Runtime `depend` entries combine explicit Arch requirements with a fail-closed mapping of `DT_NEEDED` from filmcraft and filmcraft-cli. Unknown sonames stop packaging. `glibc>=X.Y` is measured from the maximum GLIBC symbol version across those ELFs. Optional X11, Wayland, portal, VA-API and AMD Vulkan-driver support are recorded as optdepends. Names use the Arch package database: [gcc-libs](https://archlinux.org/packages/core/x86_64/gcc-libs/), [libva](https://archlinux.org/packages/extra/x86_64/libva/), [libva-mesa-driver](https://archlinux.org/packages/extra/x86_64/libva-mesa-driver/), [vulkan-icd-loader](https://archlinux.org/packages/extra/x86_64/vulkan-icd-loader/), [alsa-lib](https://archlinux.org/packages/extra/x86_64/alsa-lib/), [libxkbcommon](https://archlinux.org/packages/extra/x86_64/libxkbcommon/), [vulkan-radeon](https://archlinux.org/packages/extra/x86_64/vulkan-radeon/) and [xdg-desktop-portal](https://archlinux.org/packages/extra/x86_64/xdg-desktop-portal/).

The helper creates gzip-compressed .MTREE with root ownership; its manifest includes .PKGINFO, .INSTALL and usr/ but excludes .MTREE. `.INSTALL` (post_install/post_upgrade/post_remove) mirrors `postinst.sh` and refreshes desktop, MIME and icon caches. Package and SHA256SUMS are staged together then published by no-clobber directory rename. Hash/publication failure removes the private staging directory; existing output is preserved. No synthetic .BUILDINFO is emitted; record the Linux Mint build host in the external migration manifest and do not claim Arch installation/runtime acceptance from static checks.

From the 0.11.0 repo root, after guarded x86_64 release binaries are ready:

```sh
rtk env \
  CARGO_TARGET_DIR=target \
  FILMCRAFT_DEB_ARCHES=x86_64 \
  FILMCRAFT_PACKAGE_VERSION=0.11.0-1 \
  FILMCRAFT_ARCH_PACKAGE_VERSION=0.11.0-1 \
  FILMCRAFT_BIN_DIR_X86_64=target/release \
  FILMCRAFT_DEB_WORK=target/deb-multiarch \
  FILMCRAFT_DEB_DIR=../dist-test/0.11.0/ubuntu-amd64 \
  FILMCRAFT_ARCH_PACKAGE_DIR=../dist-test/0.11.0/arch-x86_64 \
  bash packaging/linux/build-deb.sh
```

The Debian helper retains its `x86_64/` subdirectory; Arch emits `filmcraft-<pkgver>-x86_64.pkg.tar.zst` plus `SHA256SUMS` directly into its output directory. The synthetic test `bash packaging/linux/test_arch_package.sh` uses `/usr/bin/true`; it validates archive members, PKGINFO/MTREE, GLIBC floor and dependency mapping, checksum, .INSTALL hooks, fail-closed ELF checks, hash/publication rollback and clean reruns. No real application package is generated by the test.
